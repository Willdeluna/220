Core Concept

ATA 31 = data processing + display + crew interface→It takes aircraft data, processes it, displays it, alerts the crew, and records it.big picture
It is not usually the source of the data→ATA 31 is the translator and presenter. Bad data can make a good display look wrong.
Think input → process → display → alert → record→That flow keeps troubleshooting clean.
🔄

System Architecture

Core flow: sensors → DMC → IPC → AFDX → displays→DMCs collect system data, IPCs process and route it, displays show it.
DMC = data concentrator→It gathers analog, digital, and discrete signals and converts them into usable aircraft data.
IPC = integrated processing cabinet→Think of it like the aircraft server rack.server rack
🌐

IMA / AFDX Network

A220 uses Integrated Modular Avionics→It is a networked computer architecture, not a bunch of isolated standalone boxes.
AFDX Ethernet moves data fast→High-speed network routing replaces the old-school mindset of only point-to-point wiring.
Network faults can cascade→A single processing or routing issue can appear as multiple system complaints.MX clue
🧊

IPC Protection

IPC houses computing modules and digital switches→It supports FMS, OMS, data link, and display processing.
Cooling matters→If IPC temperature gets too high, it can shut off and require reset after cooling.
Cooling faults can look like avionics failures→Do not chase software until cooling and power are checked.don’t skip
📦

DMC Details

DMC converts many signal types into aircraft data→Analog, digital, and discrete signals become display/alert/recording data.
DMC also supports EICAS, flight guidance, and autothrottle logic→It is more than a passive data box.
Dual channels compare data→Channel A and B cross-talk helps prevent incorrect information from being trusted.
🖥️

Display System / EFIS

Five display units show flight, nav, engine, and system data→The displays present information; they do not create the source data.
Displays have internal cooling fans→Display complaints can still be power or cooling related.
Critical data can bypass the main network→Some IRS, ADC, EEC, and PFCC inputs can go direct when needed.critical path
🔁

Display Reconfiguration

Displays auto-reconfigure after failures→The system prioritizes keeping PFD and EICAS visible.
Half PFD, mini-map, and shared display modes can appear→Weird layout does not always mean malfunction — it may be reversion logic.
Even heavy display failures preserve critical data→Flight-critical information gets priority over convenience.safety priority
⚖️

Comparator Logic

System compares airspeed, altitude, attitude, and engine data→Disagreement creates flags and EFIS MISCOMPARE messages.
Mismatch does not automatically mean failure→It means the system sees disagreement and wants the crew/MX to verify the source.
Red flags usually mean missing or invalid data→Think sensor issue or data-path issue before screen replacement.
⚠️

EICAS / CAS

EICAS is the main MX clue machine→It displays parameters, generates CAS messages, and supports the warning system.start here
CAS tells what is wrong, not always why→Red = warning, amber = caution, cyan = advisory, white = status.
Some alerts are inhibited during critical phases→Takeoff and landing inhibition reduces nuisance alerts when crew workload is highest.
📊

Synoptic Pages & ECL

Synoptic pages visualize systems→HYD, ELEC, FUEL, and AIR pages show status, flow, and abnormal indications.
Color coding speeds troubleshooting→Green normal, amber caution, red limit exceeded.
Electronic Checklist integrates with CAS→The airplane helps guide procedures based on active faults.
🎛️

ICCP / Digital Switching

Cockpit switches are digital data inputs→ICCP panels use CAN bus, PIM modules, and RDCs.
Switches are not always direct controls→They request actions through the digital system.
CONTROL PANEL FAULT points to communication or module issues→Think PIM, RDC, or bus communication.
📼

Clock & Flight Data Recorder

Clock time comes from GNSS first→Time supports logs, FDR data, and system records.
FDR records around 2000 parameters→It runs when an engine is running or the aircraft is airborne.
FDR depends on DMC data→If recorded data is bad, trace the DMC/source path before blaming the recorder.source first
🔧

Troubleshooting Flow — Display → Data → Source

Step 1: Check CAS / EICAS→Let the airplane tell you what it thinks is wrong.
Step 2: Identify which data is missing or incorrect→A blank, flag, or miscompare is a clue to the data path.
Step 3: Compare left vs right→Use channel comparison to isolate source, processing, or display-side issues.
Step 4: Trace back DMC → IPC → source system→Don’t fix the screen until you prove the data feeding it is good.line MX rule
